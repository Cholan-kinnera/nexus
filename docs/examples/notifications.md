# Notifications & Activity Logs Developer Examples — Nexus PM

This guide provides practical developer integration examples for the Nexus PM notifications feed and activity audit logs API.

---

## Related Documentation
* [API Architecture](../../docs/api_architecture.md)

---

## Workflow

```
Client (Auth Header)
   ↓
FastAPI Backend (Read unread counts / fetch feed)
   ↓
PostgreSQL DB (Select query scoped to User ID)
   ↓
Response Client (JSON notifications page)
```

---

## Available Endpoints

| Method | Path | Purpose | Authentication Required | Role Required |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/api/notifications` | Retrieve all notifications for the authenticated user (Paginated). | Yes | None |
| `GET` | `/api/notifications/unread` | Retrieve unread notifications for the user. | Yes | None |
| `GET` | `/api/notifications/count` | Get total count of unread notifications. | Yes | None |
| `POST` | `/api/notifications/read-all` | Mark all unread notifications as read. | Yes | None |
| `PUT` | `/api/notifications/{notification_id}/read` | Mark a single notification as read. | Yes | None |
| `GET` | `/api/activity-logs` | Retrieve audit trails logs for projects user participates in. | Yes | None |

---

## Example Requests

### 1. Get Unread Notifications Count
```bash
curl -X GET "http://127.0.0.1:8000/api/notifications/count" \
     -H "Authorization: Bearer your_access_token_here"
```

### 2. Mark All Notifications as Read
```bash
curl -X POST "http://127.0.0.1:8000/api/notifications/read-all" \
     -H "Authorization: Bearer your_access_token_here"
```

### 3. Fetch Activity Audit Logs
```bash
curl -X GET "http://127.0.0.1:8000/api/activity-logs?page=1&limit=5" \
     -H "Authorization: Bearer your_access_token_here"
```

## Validation Rules
* **Pagination Parameters:** Accept optional `page` (default 1) and `limit` (default 20, max 100) query parameters.
* **Notifications:** Generated by system hooks triggered during actions (e.g. member invitation, task assignment). Users cannot create notifications directly via the API.

---

## Authentication Requirements
* Valid JWT Access Token in the Authorization header.
* Feeds are securely isolated by the database query context (e.g., scoping `Notification.user_id == current_user.id`).

---

## Developer Notes
* Notifications contain an optional `metadata` JSON field, which includes payload details like the redirect `project_id` or `task_id` for frontend navigation.
* Activity logs are automatically generated by the services layer on mutations to provide an immutable trail of project activities.
